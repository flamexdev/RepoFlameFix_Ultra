# Security Policy

## Supported Versions

RepoFlameFix Ultra (RRFU) is currently under development. Until versioned releases and a support policy are established, security fixes are handled on a best-effort basis.

| Version | Security support |
|---|---|
| Development builds | Best effort |
| Published releases | As stated in the relevant release notes |

## Reporting a Vulnerability

Please do not report exploitable security vulnerabilities in public issues or discussions.

Use GitHub's **Private vulnerability reporting** feature if it is enabled for this repository:

https://github.com/flamexdev/RepoFlameFix_Ultra/security/advisories/new

If private vulnerability reporting is unavailable, contact the repository owner through a verified contact method listed on the GitHub profile and request a private channel. Do not include exploit details in a public issue.

When reporting, include as much of the following as you can safely provide:

- A clear description of the vulnerability.
- The affected version, commit, or component.
- Steps to reproduce the issue or a proof of concept.
- The potential impact.
- Any suggested mitigation.

Please avoid sharing real API keys, access tokens, passwords, private repository contents, or personal data. Redact sensitive information from logs and screenshots.

## What to Expect

The maintainer will review the report and may ask for additional information. Please allow reasonable time for investigation and a fix before publicly disclosing the issue.

There is currently no guaranteed response or remediation time while RRFU is under development.

## Scope and Responsible Disclosure

This policy covers security issues in RRFU itself, including its handling of credentials, repository contents, AI provider integrations, file operations, and generated code changes.

Do not access, modify, or expose data that does not belong to you. Test only in environments you own or are explicitly authorized to assess.

Thank you for helping keep RepoFlameFix Ultra and its users safer.
