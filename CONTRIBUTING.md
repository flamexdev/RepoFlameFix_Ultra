# Contributing to RepoFlameFix Ultra

Thank you for your interest in contributing to **RepoFlameFix Ultra
(RRFU)**.

RRFU is an AI-powered repository analysis and repair project currently
under development. Contributions, suggestions, bug reports, and
constructive feedback are welcome.

## Before You Contribute

-   Check the existing issues and discussions before opening a new one.
-   Keep proposals focused and explain the problem they solve.
-   Be respectful and constructive when communicating with others.
-   Do not submit secrets, API keys, passwords, private repository data,
    or other sensitive information.

## Reporting Bugs

When reporting a bug, include:

1.  A clear title and description.
2.  Steps to reproduce the issue.
3.  Expected behavior and actual behavior.
4.  Relevant error messages or logs, with secrets removed.
5.  Your operating system, Python version, and RRFU version or commit,
    when applicable.

Please do not include real API keys or private credentials in issue
reports.

## Suggesting Features

Feature suggestions should explain:

-   The problem or use case.
-   The proposed behavior.
-   Why the feature would be useful.
-   Any relevant examples or alternatives.

Large changes should be discussed before implementation so effort is not
wasted on a direction the project does not intend to take.

## Submitting Changes

1.  Fork the repository.
2.  Create a branch for your change.
3.  Make a focused set of changes.
4.  Test your changes where possible.
5.  Review your diff and remove unrelated edits.
6.  Open a pull request describing what changed and why.

Use clear commit messages and include relevant testing details in the
pull request.

## Code and Security Expectations

-   Prefer readable, maintainable code over unnecessary complexity.
-   Handle errors clearly; do not silently ignore failures.
-   Never hard-code API keys, tokens, or passwords.
-   Avoid destructive file operations unless they are explicit and
    safely guarded.
-   AI-generated fixes should be reviewed and tested before being
    treated as reliable.
-   Do not claim a vulnerability or repair is confirmed unless it has
    been validated.

## Pull Request Checklist

-   [ ] The change has a clear purpose.
-   [ ] The code and documentation are updated where needed.
-   [ ] Relevant tests or manual checks have been performed.
-   [ ] No secrets or personal data are included.
-   [ ] The pull request explains limitations or known issues.

## Current Project Status

RRFU is under active development. Contribution guidelines and project
architecture may evolve as the project grows. Not every proposed feature
will necessarily be accepted.

Thank you for helping improve RepoFlameFix Ultra.
